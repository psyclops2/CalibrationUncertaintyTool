# 校正証明書出力の仕様案

状態：検討案。既存機能の変更は未実施。

## 文書の役割

現在のレポートは「不確かさ計算手順書」として維持する。校正証明書は、同じモデル・入力・評価結果を使って作成する別文書とする。手順書から式やバジェットを隠して証明書にする方式にはしない。

参考PDFは表紙1ページと、直流電圧・直流電流・抵抗・TC・RTDの結果ページで構成される。証明書番号・発行日・ページ番号は各ページで繰り返し、表紙には依頼者、機器、実施場所、環境条件、校正日、発行機関、責任者を記載する。結果ページには項目・方法・条件・結果表・不確かさの説明・注記がある。TC・RTDでは電気量と温度換算の参考値を別の列にしている。

これは参考例の構成整理であり、認定制度の必須項目を判定したものではない。例の認定マークや認定を表明する文章を標準テンプレートへ転載・自動付与しない。

## 保存する情報

| 区分 | 内容 | 入力・取得方法 |
|---|---|---|
| 証明書情報 | 証明書番号、発行日、校正日、依頼者名・住所、実施場所 | 証明書用に入力 |
| 校正対象 | 品名、製造者、型式、製造番号、管理番号 | 証明書用に入力 |
| 発行者 | 機関名、住所、責任者、ロゴ・署名画像、採用する定型文 | 入力。再利用用の既定値を持たせても採用内容はプロジェクトへ保存 |
| 校正項目 | 項目名、方法・手順書番号、条件、環境、注記 | 項目単位で設定。全体共通の条件を継承し、異なる条件を明示 |
| 結果表 | 対象点、順序、列名、列の取得元、単位、表示桁 | 計算データとの対応付け |
| 表示様式 | HTML、CSS、言語、用紙、画像 | テンプレートと使用した資材を保存 |

現在の文書情報の番号・改訂履歴は計算手順書の情報であり、証明書番号・発行日・責任者へ流用しない。証明書用データは独立した任意項目としてJSON/CUTPへ追加する。証明書の情報がない旧ファイルはそのまま使用できる。

## 結果表と計算値の対応

表の列は固定した電圧用項目にはせず、列名と取得元を設定する。

- 点ごとの記載値：レンジ、公称値、設定値、周波数、試験電流、備考など、計算に存在しない記載事項。
- 既存の量：その点の入力量の中心値、モデルから計算した出力量の値。
- 評価結果：指定した出力量に対応する標準不確かさ、拡張不確かさ、包含係数、採用した包含条件。

公称値やレンジを校正点名から解析しない。計算に使っている値があれば、それを参照して転記を減らす。記載だけに必要な条件をモデル式へ追加させない。

例えば電圧比較のVは指示値の差なので、そのまま「校正値」とは呼ばない。「指示誤差」等の適切な列名でVを採用する。別の意味の校正値や補正値が必要なら、その出力量をモデルで定義して選択する。証明書のテンプレートへ足し引き・符号反転・温度換算を実装しない。

結果値と不確かさは、同じ点・同じ出力量・同じ計算状態から取得する。表示単位の倍率と丸めはセットで適用する。最初はモデルの単位を標準とし、表示単位を変える場合は明示的な倍率換算に限定する。

「参考値」「認定範囲外」などの区分は、項目・行・必要なら列へ注記として対応付ける。TC/RTDの参考例のように、一つの行に証明対象の電気量と参考の温度が共存しても区別できるようにする。数値や値の大小から区分を自動判定しない。

## 不確かさと未評価値

kや包含条件は計算結果から取得する。テンプレートへ「k=2、約95%」を固定記載しない。項目内で条件が同じなら共通の説明にまとめ、異なる場合は行のk列や注記で示す。手動指定したkだけから包含確率を推定しない。

計算済みの0、拡張不確かさ未評価、表示しない参考値を区別する。欠落を0やダッシュで埋めた完成文書を生成しない。参考例のダッシュも、単にUが空だからという理由で模倣しない。指定した結果列に計算エラーがあれば、その行と原因を示し、通常の証明書出力を止める。

## レポートタブの操作

タブ自体は増やさず、先頭に文書種別として「不確かさ計算手順書／校正証明書」を置く。

証明書側では「証明書情報」「結果表の設定」「書式」の設定を必要なときだけ開く。結果表では校正項目を追加し、対象点と列を対応付ける。通常の作業でHTMLを編集する必要はない。テンプレートを変更したい場合だけHTML/CSSを編集・読み込みする。

操作は、証明書情報と対象機器の入力 → 校正項目・対象点・列の指定 → プレビュー確認 → HTML保存。設定済みなら該当箇所だけ変更できる。保存先へ出力するまで、プレビューは下書きとして扱う。

初版は一つのプロジェクトと一つの校正対象を扱い、複数の結果表を構成できるようにする。参考PDFのような多機能機器で複数のモデルファイルが必要な場合は、別途複数プロジェクトの結果をまとめる機能が必要となる。今回、そのために外部参照やモデル構造を変更しない。

## HTML/CSSテンプレート

標準のブランク様式として、表紙と繰返し可能な校正項目ブロックを用意する。HTMLは文書構造、CSSは文字・余白・罫線・印刷時の改ページを担当する。

処理は「計算結果を取得 → 証明書用のデータを確定 → テンプレートへ差込み → 完成HTML」とする。テンプレートは計算用データやQtウィジェットを直接参照せず、証明書用に提供された項目だけを使用する。利用者が記入した文は通常の文字列として差し込み、任意コードの実行や計算処理は提供しない。

現在のプレビューはQTextEditなので、ブラウザと同じCSS・改ページになる前提にはできない。初版は完成HTMLをブラウザで確認・印刷する方式を基準とし、タブ内の簡易表示を印刷結果と同一とは扱わない。用紙サイズ、表のヘッダ繰返し、行分断、長い注記、ページ番号は、対象ブラウザで印刷して確認する。アプリ内の印刷同等プレビュー・直接PDF保存は、その描画方式を決めてから追加する。

ロゴ等の画像は既存の画像資材へ取り込み、テンプレートも採用内容をCUTPへ保存する。外部ファイルのパスだけを保持せず、別PCやテンプレート原本の変更後も再生成できるようにする。生成HTMLはCSSと画像を含む単独ファイルとし、後でモデルを編集しても保存済みHTMLの内容は変わらない。

## 実装の境界と確認事項

現在のレポートは計算タブを動かして表示値を取得している。証明書側へこの依存を増やさず、対象点・出力を指定して、数値・単位・包含条件・エラーを得る処理を共通化する。証明書の追加に合わせた計算式・不確かさ評価の変更はしない。

初版で確認するのは、電圧3点の指示誤差表、複数出力、条件の異なる項目、参考列、点ごとに異なるk、未評価U、長い依頼者住所・注記、複数ページ、日英表示、画像、保存・再読込、入力変更後の更新である。既存の計算手順書の数値・出力が変わらないことも確認する。

証明書の番号自動採番、承認・電子署名、発行履歴管理、複数CUTPの合冊、CMC・適合判定の自動処理は、この初版に含めない。これらを出力レイアウトの追加に紛れ込ませない。
