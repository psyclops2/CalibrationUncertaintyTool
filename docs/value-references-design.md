# 値の参照と自動計算の設計案

状態：実装済み。以下は検討時の設計を残したもの。現在の操作は[参照式の設定手順](reference-formula-usage.md)、初期実装との対応は末尾を参照。

## 目的と対象

ソフト内に入力した数値を別の入力欄の計算式から参照し、参照元の変更を計算結果へ反映する。最初の利用先は、標準器の仕様係数、レンジ基準値、校正点の値からType Bの半値幅を求める処理とする。

仕様を固定した分類へ当てはめず、数値と式を自由に組み合わせる。`ppm of reading + ppm of range`は利用例であり、専用のデータ構造にはしない。DB化、日常校正用モード、CMC比較は今回の実装範囲に含めない。計算設定は従来どおり共通管理する。

検討開始前の保存点は `d48610f`。既存ブランチ `1.00.01` へpush済み。検討は `codex/value-reference-design` で行う。

## 現在の実装から分かったこと

| 箇所 | 現在の動作 | 参照機能に必要な変更 |
|---|---|---|
| `variables_tab_handlers.py` の `on_calculate_button_clicked` | 選択中の校正点の変数の中心値を集め、式の結果を半値幅に書き込む | 式を継続的な定義として扱い、選択していない点でも評価する |
| `ValueHandler` | 辞書に保存された値を読み出す。式の評価状態は持たない | 有効な評価結果と未入力・参照切れを区別する |
| `model_equation_tab.py` の式変更処理 | 式から削除された変数のデータを破棄する | 仕様係数などは測定モデルの変数と別に保持する |
| `PointSettingsTab` | 点の名前と、各変数の `values` 配列を並べ替える | 特定の点を参照するときに、位置ではなく同じ点を追跡する |
| `MainWindow.get_save_data` | A/B/固定値に応じた許可キーだけを保存する | 参照定義・IDを保存対象に追加する |
| `BulkInputDialog`、A/B入力ハンドラ | 複数の経路から辞書へ直接値を書き込む | どの入力経路でも依存する式を無効化する |
| 通常計算・レポート・モンテカルロ | 保存済みの値を読む。レポートは計算タブを呼び出して計算する | 同じ評価結果を渡し、古い値を使わない |

既存の計算ボタン処理を呼び出した確認では、`x=3`、式 `math.fabs(x)*20e-6+10*5e-6` から半値幅 `0.0001100` が得られた。その後、参照元の保存データ `x` を4へ変更しても半値幅は `0.0001100` のままで、標準不確かさの読み出しも以前の値を返した。他の校正点の半値幅は未計算のままだった。入力ハンドラも同じ保存データへ直接書き込む構造である。新しい仕組みでは、それぞれ `0.0001300` と、その点の入力に応じた評価結果になる必要がある。

## 利用者から見た操作

1. 「参照値」の一覧に、よく使う数値を名前・値・単位・説明とともに登録する。係数やレンジ基準値もここに置ける。名称やグループは利用者が決める。
2. Type Bの半値幅で「直接入力」か「参照式」を選ぶ。
3. 式の編集時に「参照を挿入」から値を選ぶ。選択時には、名前、項目、共通値／校正点の値、現在値、単位を表示する。
4. 式・参照先・代入値・評価結果を確認する。参照元を変更すると半値幅と標準不確かさが更新される。
5. 全校正点のプレビューで、レンジ変更や測定点の違いによる結果を確認する。

式の例は次のとおり。`@{...}` は参照を識別するための構文案で、画面では名前付きの参照として表示する。

```text
abs(@{reading}) * @{reading_ppm} * 1e-6
  + @{range_value} * @{range_ppm} * 1e-6
```

`reading` は現在評価している校正点の変数の中心値、`range_value` はその点で指定したレンジ基準値を参照する。`reading_ppm` と `range_ppm` は共通の参照値を参照する。係数はppm単位の数値として入力し、式の `1e-6` で倍率へ換算する。参照機能が二重にppm換算しない。

| 条件 | reading項 | range項 | 半値幅 |
|---|---:|---:|---:|
| reading=3 V、range=10 V、20 ppm + 5 ppm | 60 µV | 50 µV | 110 µV |
| reading=4 V、その他は同じ | 80 µV | 50 µV | 130 µV |
| reading=3 V、range=100 V、係数は同じと仮定 | 60 µV | 500 µV | 560 µV |

実機ではレンジによって係数も変わり得る。レンジ名から係数を選ぶ表や条件式は、この参照基盤の上で追加する。初期実装でレンジから仕様を推測したり、自動的に最良のレンジを選んだりしない。

## アドレスと校正点の扱い

アドレスは画面部品や配列位置を指さず、データの対象IDと項目を指す。画面の並べ替えやタブ名変更が参照へ影響しない構造にする。

| 参照の種類 | 意味 |
|---|---|
| 共通の参照値 | 全校正点で同じ値 |
| 校正点ごとの参照値 | 評価対象の点に登録した値 |
| 変数の現在点の項目 | 評価対象の点にある中心値など |
| 変数の特定点の項目 | 指定した点のIDに結び付いた値 |

「現在点」は画面で選択している点ではなく、計算処理へ明示的に渡した点とする。レポートや一覧を計算しても、画面の選択は変更しない。

表示名と保存用IDを分ける。式では短い参照名を使い、別の対応表で実際のアドレスへ結び付ける。

```json
{
  "expression": "abs(@{reading}) * @{a} * 1e-6 + @{range} * @{b} * 1e-6",
  "bindings": {
    "reading": {
      "kind": "variable_field", "variable_id": "var-x",
      "field": "central_value", "point": {"mode": "current"}
    },
    "a": {"kind": "reference_value", "value_id": "reading-coefficient"},
    "b": {"kind": "reference_value", "value_id": "range-coefficient"},
    "range": {
      "kind": "reference_value", "value_id": "selected-range-value",
      "point": {"mode": "current"}
    }
  }
}
```

上のIDは説明用。実際はIDを自動採番し、利用者には名前と対象を示す。式内の参照名を変える場合は対応表も更新する。IDの手入力は通常操作にしない。

点の追加では新しいIDを発行し、並べ替えではIDと値を一緒に移動する。特定点を削除したら参照エラーにし、隣の点へ結び直さない。点の複製を追加する際は新しいIDとし、現在点参照は複製先、特定点参照は元の明示対象を維持する。

変数名の変更については追加の対応が必要になる。現在の式変更処理は削除と追加として扱うため、IDを設けるだけでは参照を維持できない。明示的な名前変更操作でIDを維持するか、新旧変数の対応を利用者に指定してもらう。単なる式の書き換えから同一変数だと推測しない。

## 計算処理の構成

入力データ、参照の解決、数式評価、表示を分ける。

```text
入力データと参照定義
       ↓ 評価対象の校正点IDを指定
参照の解決と依存順序の決定
       ↓
Decimalによる式評価
       ↓
半値幅の検証 → 分布・除数による標準不確かさの計算
       ↓
評価結果と状態 → 入力画面／バジェット／一覧／レポート
```

参照式からQtウィジェットを読み出さない。許可されたデータ項目だけを解決し、JSONの任意パスやPythonの属性アクセスは認めない。既存のAST評価を部品として利用できるが、現在の `evaluate_formula` は失敗を `None` にまとめるため、参照エラー・構文エラー・数値エラーを区別して返す入口を追加する。参照文字列を数値文字列で単純置換して `eval` に渡さない。

最初に編集可能な計算先は、Type Bの半値幅と参照値の数式とする。参照元は参照値と入力変数の中心値から開始し、他の数値項目は項目ごとの提供処理を追加して拡張する。自由記述、測定値列全体、表示用文字列はそのまま数値参照にしない。

半値幅の式は変数に共通の定義を持ち、各校正点で評価する。点ごとの式変更も明示的な上書きとして表現する。共通式があっても、数値結果を全点で共有しない。

計算結果は `valid`、`missing`、`error`、`dirty` を区別し、数値・単位・原因のあるアドレスを保持する。参照先削除、空欄、NaN/Infinity、ゼロ除算、循環参照、負の半値幅は有効な数値へ置き換えない。ゼロは正常な数値として扱う。

循環は参照値同士の式やType Bの派生処理を含めて検出する。共通値の式が「現在点」を必要とする場合は、校正点ごとの値として定義するよう求める。どの点の値か不明なまま共通値を計算しない。

## 入力変更と再計算

現在は辞書を直接書き換える箇所が多いため、入力欄のシグナルだけをつなぎ足すと、一括入力や読込を取りこぼす。参照機能に関係する変更を通知する共通の窓口を設け、個別入力、一括入力、点操作、式変更、読込から呼び出す。

変更直後に該当結果を `dirty` とし、短い入力待ち時間を設けて軽い式評価を行う。初期版では有効な全参照式を依存順に評価してよい。実測で負荷が問題になった場合に、変更された値の依存先だけを評価する最適化を追加する。

表示更新中は入力シグナルを抑制し、表示した結果を手入力の変更として扱わない。直接入力と参照式は一つの項目に対する排他的な入力方法とする。式を使っている半値幅へ手入力する場合は、直接入力へ切り替える操作を明示する。一括入力からも式を黙って上書きしない。

計算の入口で、入力データと参照定義から評価結果を確定する。バジェット、一覧、保存前、レポート、モンテカルロ開始前に未評価の変更がないことを確認する。タイマーがまだ発火していない場合でも、以前の値で計算しない。参照が不正な点は不正状態として返し、無関係な点は評価できるようにする。

一回の計算では同じ入力の写しと評価結果を使用する。計算途中で画面の選択や入力が変わっても混在させない。評価関数は読み出しのたびに保存データを書き換えず、依存関係を計算した後で結果をまとめて反映する。

モンテカルロは参照変更時に結果を未更新として表示し、実行は利用者の指示で行う。参照値の変更をきっかけに自動実行しない。

## 不確かさ伝播との境界

標準器の仕様から半値幅を評価する参照式と、測定対象量のモデル式は別の定義である。

例として `Y = x + e`、`e` の中心値が0、`e` の半値幅が `abs(x)*a + R*b` の場合、参照式は各点の推定値 `x` に対する半値幅を決める。これを自動的に `Y = x + abs(x)*a + R*b` へ展開しない。半値幅を補正値として加算しない。

同じ値を参照することだけから、入力量の相関係数を自動設定しない。数値の参照関係と、確率的な依存関係を別に扱う。初期版のモンテカルロでは推定値から評価した半値幅を分布パラメータとして使用し、サンプルごとに参照式を再評価する条件付き分布は導入しない。

中心値そのものを参照式で導出する機能は、測定モデルの依存関係、感度係数、相関との対応を検討してから追加する。アドレス解決が可能だからという理由で、すべての計算欄を同時に参照式へ変更しない。

## 単位と数値の取り扱い

参照する値には、少なくとも元の数値と単位を表示する。現在の単位パーサは次元を返すもので、倍率を含む単位変換器ではない。次元一致だけで `mV` と `V` の値を同一倍率として演算しない。

初期版で自動単位変換を導入しない場合、式を評価する数値の単位を明示し、異なる単位の変換倍率は式内に記述する。ppm係数の数値表現も式の説明に明記する。換算機能を追加する際は倍率とオフセットを含めて別途検証する。既存パーサで解析できない単位を、無次元として黙認しない。

参照値は計算途中で表示桁へ丸めない。計算は共通設定の精度を使用し、丸めは表示・出力時に行う。分布と除数は従来のType B設定として維持し、仕様の式から自動推定しない。

## 保存と既存データの移行

保存するのは入力値と式、参照先ID、校正点の適用範囲である。画面に表示した計算結果だけを保存して、式との結び付きを失わないようにする。

保存項目の案は、機能版を示す `value_reference_version`、変数名とIDの対応、校正点IDの配列、`reference_values`、`field_expressions`。参照用IDは既存の `values` 配列を保ったまま位置との対応を持たせ、点操作で必ず一緒に更新する。参照定義はトップレベルに保持し、既存のtype別保存処理で消されないようにする。

旧JSONを読んだ際は従来動作を維持し、参照機能を有効にするときに一度だけIDを付与する。画面を読むたびにIDを作り直さない。既存の `calculation_formula` は手動計算の定義として残し、参照式へ明示的に取り込むまで自動計算へ切り替えない。

読込時はIDの重複、参照先、対応する点、対象項目を検証する。構造が壊れたファイルは反映しない。意図的な削除などで参照先が失われた場合は、その式をエラー状態で保持し、利用者が参照を修正できるようにする。

有効な計算結果は既存の数値欄にも反映できるが、読込時は式から再評価する。エラー時に以前の数値を有効な入力として残さない。入力途中の不正な式はエラー状態のまま保存・復旧できるようにし、保存を全面禁止しない。

旧版アプリには新しい参照定義を保持する処理がないため、新版で保存したファイルを旧版で再保存すると定義が失われ得る。既存JSONを読めることと、新しいファイルを旧版で編集できることは区別する。新機能の保存形式には版を付け、対応外の版の扱いを決める。

## 実装順序と確認条件

| 段階 | 実装 | 確認すること |
|---|---|---|
| 1 | アドレス、参照解決、式評価の独立した処理 | Qtなしで共通値・現在点・特定点・循環・参照切れを評価できる |
| 2 | IDと参照定義の保存・読込 | 旧JSONの維持、保存往復、点の並べ替え・削除でも参照先を取り違えない |
| 3 | 参照値の編集とType B半値幅への接続 | 係数、reading、レンジの変更が全対象点の半値幅・標準不確かさへ反映される |
| 4 | 一括入力・バジェット・一覧・レポートとの接続 | 入力直後、タブ未表示、タイマー待ち中でも同じ結果を使う |
| 5 | モンテカルロの入力接続と結果の無効化 | 実行前の評価が一致し、入力変更時は古い結果を未更新として示す |

代表的な検証ケースは以下のとおり。

- 3 V、10 Vレンジ、20 ppm + 5 ppmから110 µVを得る。readingを4 Vへ変更すると130 µVになる。
- `reading` が負でも半値幅は非負になる。ゼロと未入力を区別する。
- 点ごとにreading・レンジが異なっていても、同じ式をそれぞれの点で評価する。
- 特定点参照は並べ替え・名前変更後も同じ点を指す。削除後はエラーになり、別の点に移らない。
- 参照値を名前変更してもIDで追跡できる。別の値へ置き換えた場合は影響する式を再評価する。
- 参照先の単位変更、空欄、非数、ゼロ除算、直接・間接の循環を検出する。
- 式のエラー時に古い半値幅や標準不確かさでバジェットを計算しない。
- 直接入力と参照式の切替、一括入力、A/B/固定値のタイプ変更で参照定義を黙って失わない。
- 保存・復旧・再読込後も式と参照先を保持し、数値を再現する。
- 参照値を変更してもモンテカルロは自動実行されない。
- 既存の手動計算式、通常の数値入力、単位検証、レポートに回帰不具合を起こさない。

## 実装前に具体化する点

まず上記のアドレス解決と評価処理を作り、ppm仕様の例を画面なしで動かせる状態にする。その後、実データに合わせて参照選択UIを詰める。

参照値一覧の配置、全点共通式と点ごとの上書きの見せ方、レンジ表の選択方法、単位変換の初期対応範囲は、まだ確定していない。標準器の仕様をどこへ登録するかと、参照式をどう計算するかを分けて検討する。


## 初期実装との対応

以下は初期実装時の記録。現在は式の編集を「参照式を設定」に統一し、ツールメニューの「参照値」では共用値だけを編集する。旧手動計算UIと旧式編集タブは廃止し、旧ファイルの読込を維持している。現在の操作は[設定手順](reference-formula-usage.md)を参照。

- ツールメニューの「参照値とType B参照式」から編集する。参照値には名前、共通の数値／式、単位、説明を持たせられる。「校正点ごと」を選ぶと点別の上書きを設定できる。
- 実装の参照構文は `@{value:ID}` と `@{variable:ID:central_value:current}`。特定点では `current` を点IDに置き換える。選択一覧は表示名、内部の参照式はIDを保持する。参照名とbindingsを別に持つ案は採用せず、型付きアドレスを直接保存した。
- Type Bの入力幅には全点の基本式と点別式を設定する。現在のGUIでは対象量を選んで編集し、「直接入力へ戻す」で式を解除する。分布と除数は変数管理で設定する。
- 参照値の適用範囲が全点共通の場合、現在点参照はエラーになる。校正点ごとの参照値は対象点のデータで評価する。
- 数式評価はQtから独立した `value_references.py` が担当する。数値はDecimalで扱い、`abs` もDecimal精度を維持する。
- 保存形式はトップレベルの `value_references` に版、変数ID、点ID、参照値、半値幅式をまとめて持つ。従来の手動計算式はそのまま維持する。
- 現在の直接辞書更新を取りこぼさないため、初期版は1秒ごとに入力内容を確認して再計算する。数値読出しと保存の直前にも入力を確認する。計算済み内容が同じ場合は評価を省く。書込APIの全面統一と細かな差分更新は今後の改善として残す。
- 参照式で計算する入力幅は既存画面からの手入力を無効化し、一括入力からの上書きも拒否する。評価エラー時は幅と標準不確かさを空にする。現在の式編集画面では、不正な式や参照値は保存前の評価で受け付けない。
- 参照変更時にモンテカルロの以前の結果を消すが、自動実行しない。単位は明記した数値のまま扱い、自動換算は実装していない。
- 式編集画面では内部アドレスを名前で表示し、選択した参照をカーソル位置へ挿入する。保存は従来の型付きアドレスのままであり、データ形式は変更していない。
- 変数の明示的な名前変更、レンジ条件表からの選択、旧版アプリでの編集制限は今後の対象。モデル式で変数を削除した場合はIDの対応を除き、新しい変数に同じ名前を付けても参照を継承しない。
